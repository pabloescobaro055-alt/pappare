# Подключение ЮKassa на VPS

ShopID 1487524. Подключены «Чеки от ЮKassa», налоговый режим — патент,
НДС — «Без НДС» (подтверждено владельцем). В запросе чека услуга «Участие в киноужине»,
по одной позиции за место, сохранённая цена, vat_code=1, service, full_prepayment.
У сервиса «Чеки от ЮKassa» нет tax_system_code в опубликованном наборе параметров;
не отправляем параметр сторонних касс. Налоговый режим должен соответствовать договору магазина.

## Обновление

```bash
cd /var/www/pappare &&
git pull --ff-only origin main &&
npm run test:cinema &&
npm run build
```

Не заменять существующие CINEMA_DATABASE_URL, CINEMA_ADMIN_SECRET и настройки Telegram.
Сделать защищённую копию файла конфигурации перед редактированием:

```bash
cd /var/www/pappare
if [ -f .env.production.local ]; then cp -p .env.production.local "/root/pappare-env-$(date +%Y%m%d-%H%M%S).backup"; fi
nano .env.production.local
```

Добавить или заменить следующие переменные (секрет вписывать в nano, не в командную строку).
Не использовать буквальный текст `ВАШ_СЕКРЕТНЫЙ_КЛЮЧ`:

```dotenv
CINEMA_DEMO=false
CINEMA_PUBLIC_ORIGIN=https://pappare.ru
PAYMENT_PROVIDER=yookassa
YOOKASSA_SHOP_ID=1487524
YOOKASSA_SECRET_KEY=ВАШ_СЕКРЕТНЫЙ_КЛЮЧ
YOOKASSA_TEST=false
CINEMA_ONLINE_SALES=true
```

Сохранить Ctrl+O, Enter, закрыть Ctrl+X. Настройки вступают в силу при запуске сервера.
Переменные, ранее заданные непосредственно в PM2, имеют приоритет над файлами Next;
если они отличаются, обновить PM2 без публикации секретов. Скрипт ниже загружает актуальный
файл в окружение перезапуска и не выводит его значения:

```bash
chmod 600 /var/www/pappare/.env.production.local
cd /var/www/pappare && node scripts/restart-cinema-payment.cjs
```

## Кабинет ЮKassa

Интеграция → HTTP-уведомления: URL
`https://pappare.ru/api/cinema/yookassa/webhook`.
Подписаться на `payment.succeeded` и `payment.canceled`. Сохранять после выкладки обработчика.
Уведомления не используют HMAC старого шлюза: сервер сам получает платёж по API
и сверяет магазин, order_id, ID платежа, RUB, точную сумму, test=false и paid/status.
Значения в присланном JSON не считаются подтверждением оплаты.

## Проверка

Выбрать свободное место, ввести имя, телефон, email и принять условия. Нажать оплату:
должна открыться страница ЮKassa с суммой выбранных мест. После реального успешного платежа
проверить статус «Ваш вечер забронирован», занятость в другом браузере, заказ в админке,
уведомление «оплачено» в Telegram и чек в кабинете/на email. Реальная проверка не выполнена
разработчиком без доступа к ключу и VPS. Тестирование с подменённым API не равно проверке магазина.

Для отдельного тестового магазина использовать его ID/ключ и YOOKASSA_TEST=true.
Не включать тестовый магазин на публичной продаже: тестовые статусы могут занять реальные места.
Возвраты пока выполняет администратор в кабинете ЮKassa; оплаченные места автоматически
после возврата не освобождаются — необходимо согласовать новую бронь с гостем.

Резерв 10 минут, оплата после истечения переводит заказ в `paid_review`: деньги получены,
места не закреплены, администратору приходит предупреждение. Нельзя обещать гостю билет
до урегулирования. Такой заказ отображается в админке и на странице заказа.

После фактического оказания услуги в админке нажать для оплаченного заказа ЮKassa
«Услуга оказана — чек зачёта / проверить статус». Запрос идемпотентен: повторные клики
проверяют ранее созданный чек. Проверить статус succeeded; canceled требует обращения в поддержку.
Кнопка доступна после начала сеанса, факт оказания подтверждает администратор.

Повторная доставка сообщений в бот выполняется отдельным процессом PM2
`pappare-cinema-notifications` каждые 30 секунд. Ошибки Telegram сохраняются в базе для повторения.
Он также повторно сверяет платежи последних 24 часов и статусы чеков (до 5 за проход, по очереди),
если покупатель закрыл браузер или уведомление ещё не доставлено.
Логи: `pm2 logs pappare-cinema-notifications --lines 20 --nostream`.
