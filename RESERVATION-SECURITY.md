# Защита сайта и уведомлений ресторана

Обновление закрывает спам через форму бронирования, а не подтверждает факт взлома Telegram.
По одному скриншоту нельзя определить личность отправителя или утечку токена бота.

## Что проверяется

Обычная форма: имя не короче двух букв, российский телефон из 11 цифр без длинных
повторяющихся последовательностей, корректное время при заполнении, 1–30 гостей,
поля ограниченной длины. Проверяются JSON, размер запроса до 5 КБ, origin,
подписанный токен формы и HttpOnly SameSite cookie. Токен действует 30 минут;
слишком быстрая отправка отклоняется. Это проверка сессии, не CAPTCHA и не доказательство,
что отправитель человек. Обработчики платежей проверяют сумму и статус у ЮKassa;
отметка оплаты не принимается от браузера.

Лимиты обычной формы: 3 заявки за 10 минут с IP; 2 за 30 минут с телефона;
пауза 60 секунд для того же телефона; одинаковый телефон/время и токен повторно
не принимаются 30 минут. Общий предел 20 заявок за 10 минут. Неуспешная доставка
также расходует лимит: повторная отправка может быть отклонена, гостю следует позвонить.
С PostgreSQL лимиты сохраняются после перезапуска; без неё они находятся в памяти процесса.
В случае массового распределённого спама потребуется дополнительная CAPTCHA/WAF.

Vercel обслуживает только подписанную доставку от VPS. Прямой POST без подписи
отклоняется. Подпись включает всё тело и время; изменение тела и повторы старше минуты
не допускаются. Нельзя оставить старое приложение Vercel без обновления.

## Ключ доставки

Если на VPS и Vercel задан одинаковый TELEGRAM_BOT_TOKEN, дополнительная настройка
не нужна: из него серверы выводят ключ доставки. Если на VPS токена бота нет,
задайте одинаковый RESERVATION_RELAY_SECRET (случайные 64 hex-символа) на обоих серверах.
На VPS хранить в .env.production.local; в Vercel — Settings → Environment Variables
для Production, после изменения сделать Redeploy. Не отправлять секрет в чат и Git.

Проверка без вывода секретов:
`node scripts/check-reservation-security.cjs`

Публичный GET https://pappare.vercel.app/api/reservations после выкладки должен возвращать 403.
Для реальной формы сайта GET https://pappare.ru/api/reservations возвращает токен с cookie.
После выкладки попросите администратора один раз отправить настоящую заявку;
не проверяйте спам живыми сообщениями в рабочий бот.

## Кнопки бота

По умолчанию кнопки могут нажимать только creator/administrator целевого Telegram-чата.
Дайте доверенным сотрудникам статус администратора чата или настройте TELEGRAM_ADMIN_IDS
на сервере обработки webhook Vercel — список числовых Telegram ID через запятую.
Username не подходит. Секрет webhook сравнивается безопасно; короткая заглушка
не используется, вместо неё берётся производный секрет из токена бота.
После обновления регистрация webhook повторяется при первой настоящей заявке.

Если токен бота был опубликован, перевыпустите его в BotFather и обновите на всех
серверах. По скриншоту заявок необходимость перевыпуска не установлена.

## IP и расследование

Nginx должен перезаписывать клиентские proxy-заголовки, а не доверять присланным:
`proxy_set_header X-Real-IP $remote_addr;`
`proxy_set_header X-Forwarded-For $remote_addr;`
Если используется доверенный CDN, сначала корректно настройте real_ip для его сетей.
Не подставляйте эти строки вслепую в другую схему проксирования.

Проверка существующих заголовков:
`sudo nginx -T 2>&1 | grep -E 'proxy_set_header (X-Real-IP|X-Forwarded-For)'`

Исторические запросы к форме на VPS:
`sudo grep 'POST /api/reservations' /var/log/nginx/access.log | tail -n 30`
Если спам шёл непосредственно на Vercel, искать в его Runtime Logs.
Новые отклонённые запросы пишутся как reservation_rejected с IP, временем и кодом;
имена, телефоны, cookies, ключи и тела запросов не журналируются.
IP показывает источник соединения, но не устанавливает личность человека.

## Проверенные зависимости

Next.js обновлён до 15.5.27, PostCSS и source-map-js обновлены с overrides.
После npm ci аудит npm audit --omit=dev показывает 0 известных уязвимостей.
Полный аудит также содержит предупреждения в инструментах сборки и lint
(braces, postcss-selector-parser и зависящие пакеты). Они не входят в production-набор;
сайт не принимает от посетителей glob-шаблоны или CSS для сборки. Полная миграция
Tailwind/ESLint не выполнялась. Нулевой результат аудита не является гарантией
отсутствия неизвестных уязвимостей или заменой проверки конфигурации VPS.
