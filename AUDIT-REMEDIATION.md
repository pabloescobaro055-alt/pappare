# Разбор аудита и выполненные изменения

Дата: 9 октября 2026 года. Проверяется текущий исходный код. Состояние развёрнутых
VPS и Vercel необходимо сверить отдельно: изменения в GitHub не равны установке на сервер.
Проверки выполнялись локально, с изолированной БД и подменёнными внешними API;
рабочие заявки в Telegram и реальные платежи не создавались.

## Оценка замечаний

| Замечание | Что подтверждено | Изменения и пределы |
| --- | --- | --- |
| Открытый адрес админки и статический Bearer | Страница входа публична; старый API принимал ключ напрямую. Сам адрес не даёт прав. | Browser API теперь принимает только серверную сессию. В production обязательны ключ и TOTP; cookie HttpOnly Secure SameSite Strict, срок 1 час. Выход отзывает сессию, смена ключа/seed аннулирует старые подписи. |
| Перебор входа | В старой версии не было отдельного ограничения входа. | После 5 неверных попыток IP блокируется на 15 минут. TOTP нельзя использовать повторно. Предусмотрена настройка точного IP-allowlist; по умолчанию она выключена, чтобы не закрыть мобильный/динамический доступ владельца. |
| Произвольные файлы и stored XSS/RCE | Эксплуатация не показана. До аудита фото уже обрабатывались Sharp и хранились в БД как WebP. | Добавлены whitelist MIME, сигнатуры JPG/PNG/WebP, проверка декодируемого формата, чтение потока до 8 МБ, предел 24 млн пикселей и перекодирование без исходных метаданных. SVG/HTML/JS отклоняются. Это не доказательство отсутствия неизвестных ошибок в декодере. |
| Антибот только на клиенте | Утверждение не соответствует текущему коду; сервер проверял company и submittedAt даже ранее. | Последнее обновление уже ввело подписанный токен, HttpOnly-cookie, проверку Origin, серверную валидацию, одноразовую отправку, дедупликацию и лимиты. Глобальный лимит, блокирующий всех гостей, убран; остаются лимиты по IP и телефону. |
| Спам и доверие submittedAt | Простая отметка времени клиента сама по себе не защищает. | Возраст подтверждается серверным временем внутри подписанного токена, а не одним submittedAt. Прямой старый PoC без cookie/token отклоняется. Токен сессии не является CAPTCHA: целенаправленная автоматизация и распределённый спам остаются поводом для CAPTCHA/WAF. |
| Stored XSS и SQL-инъекции через текст | Приведён гипотетический пример, исполнение не показано. | Админка выводит строки через React, запросы к БД параметризованы, Telegram получает обычный текст. JSON-LD уже экранирует символ <. CSP добавляет дополнительный барьер. |
| Нет CSP | Подтверждено для прежней версии. | Enforced CSP с новым 192-битным nonce для каждого ответа, strict-dynamic, запретом inline-JS и eval в production, object-src none, frame-ancestors none, form-action self. Inline styles оставлены для текущего интерфейса и анимаций. |
| Fingerprinting и robots | Версии и пути раскрывались; это информация, а не самостоятельный обход авторизации. | X-Powered-By отключён. Предусмотрен server_tokens off для Nginx. Частные пути убраны из robots; админка/заказ закрыты noindex, API получают X-Robots-Tag. Заголовки не заменяют аутентификацию. |
| Webvisor и персональные данные | webvisor true был включён. | Webvisor/clickmap отключены. Метрика не инициализируется в разделе /kino, существующий счётчик уничтожается при переходе туда. Поля помечены ym-disable-keys. URL аналитики без query/hash, referrer не передаётся. Это технические меры, а не юридическое заключение по 152-ФЗ. |
| Годовой shared cache HTML | Было на статических страницах. Доказанной утечки персональных данных нет. | HTML теперь динамический и private no-store, nonce не переиспользуется. Статические изображения/JS/CSS продолжают кэшироваться. Динамический рендеринг повышает нагрузку по сравнению с прежним SSG. |

Новый случайный CINEMA_SERVICE_SECRET обслуживает только проверку платежей и повтор
уведомлений. Он не открывает админку. Старый пользовательский ключ не принимается
как сервисный. Админский ключ больше не отправляется при каждом запросе редактора.

## Установка на VPS

```bash
cd /var/www/pappare &&
git pull --ff-only origin main &&
npm ci &&
npm run test:security &&
npm run test:cinema &&
npm run build
```

До перезапуска подготовьте аутентификатор с TOTP. В production вход без настройки
второго фактора закрыт. Создание конфигурации:

```bash
cd /var/www/pappare
node scripts/setup-admin-2fa.cjs
```

Скрипт сохраняет резервную копию .env.production.local в закрытом каталоге /root,
создаёт CINEMA_ADMIN_TOTP_SECRET и отдельный сервисный секрет. Существующий ключ
администратора сохраняется. В терминале будет показан секрет TOTP: добавьте его
в аутентификатор вручную как временной код, 6 цифр, SHA1, период 30 секунд.
Не присылайте этот вывод в чат и не публикуйте screenshot/URI. Сохраните seed приватно
для восстановления доступа.

Перезапуск с обновлённой конфигурацией и сервисным ключом:

```bash
node scripts/restart-admin-security.cjs
```

Вход: https://pappare.ru/kino/admin → прежний ключ + текущий одноразовый код.
Код принимается один раз; для следующего входа дождитесь следующего кода.
Вход действует один час, затем нужно войти снова. «Выйти» отзывает текущую сессию.

Ротация по инициативе владельца, вывод содержит секреты:

```bash
node scripts/setup-admin-2fa.cjs --rotate-key --rotate-totp
node scripts/restart-admin-security.cjs
```

При ротации сохраните новый ключ и переустановите TOTP в приложении. Старые сессии
не будут приниматься после перезапуска. При утрате телефона восстановление выполняет
владелец через доверенный SSH-доступ и --rotate-totp.

## Nginx и доверенные IP

Без изменения маршрутизации/файрвола можно скрыть номер версии:

```bash
cd /var/www/pappare
sudo node scripts/harden-nginx.cjs
```

Скрипт проверяет стандартный include conf.d, запускает nginx -t и reload;
при ошибке восстанавливает предыдущий файл. Если конфигурация нестандартная,
нужно настроить server_tokens off вручную. Переопределение в server-блоке может
потребовать отдельного изменения. Номер версии после установки проверить по ответу HTTPS.

IP-allowlist включать только после подтверждения заголовков Nginx и статичного IP:

```bash
sudo nginx -T 2>&1 | grep -E 'proxy_set_header (X-Real-IP|X-Forwarded-For|X-Forwarded-Proto)'
```

В .env.production.local CINEMA_ADMIN_ALLOWED_IPS содержит точные адреса через запятую.
Подсети/CIDR сейчас не поддерживаются. Для динамического LTE оставьте пустым.
Nginx должен перезаписывать клиентские proxy-заголовки доверенным адресом.

## Что ещё требует настройки или отдельного решения

Внешний SSO не подключён: реализована локальная двухфакторная аутентификация.
CAPTCHA не активирована — нет ключей выбранного сервиса. Сессионный токен не является
доказательством присутствия человека. Настройки WAF/провайдера и безопасность SSH/ОС
не проверялись через прямой доступ к VPS. Текущая проблема LTE разбирается отдельно.

Доставка обычных броней по-прежнему использует Vercel; вопросы размещения и передачи
персональных данных, правового основания аналитики и текстов политики требуют
отдельной проверки владельца. Старые записи Webvisor автоматически не удаляются:
их обработка выполняется владельцем в кабинете Метрики.

После работы хостинга отключите предоставленный техподдержке временный SSH-доступ.
Обновите Vercel вместе с VPS: старый отдельный endpoint доставки нельзя оставлять
на прежнем обработчике. Полная невозможность атак и отсутствие неизвестных уязвимостей
не заявляются.
