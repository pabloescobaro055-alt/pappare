# Обновление PAPPARE на VPS

Репозиторий: https://github.com/pabloescobaro055-alt/pappare, ветка main.
Код включает /kino, /kino/admin, /kino/terms и /kino/privacy.
Онлайн-продажи намеренно закрыты до интеграции ЮKassa. Ручное управление бронями работает с PostgreSQL.

## Перед обновлением

Уточнить действующую папку сайта, пользователя приложения, порт и способ запуска (PM2, Docker или systemd). Эти значения в текущем сеансе не получены; команды ниже нельзя выполнять с выдуманными именами служб. Не заменяйте работающую конфигурацию Nginx или Telegram relay.

Сохранить резервную копию базы PostgreSQL и действующего env-файла вне Git. Записать текущий коммит: git rev-parse HEAD. Убедиться, что git status --short не содержит серверных изменений; не применять reset --hard.

Использовать Node.js 24 LTS, npm. В репозитории есть package-lock.json для npm ci. Если сервер использует pnpm, pnpm-lock.yaml тоже обновлён.

## Настройки

В папке приложения отредактировать существующий .env.local, сохранив настройки Telegram, relay и базы. Не копировать .env.example поверх рабочего файла.

Обязательные настройки кабинета:

- DATABASE_URL: реальное подключение PostgreSQL, пользователь должен иметь права создавать таблицы в своей базе.
- CINEMA_ADMIN_SECRET: случайный секрет не короче 32 символов; сгенерировать на VPS командой openssl rand -hex 32. Не присылать секрет в чат.
- CINEMA_DEMO=false: включает реальные записи и отправку уведомлений.
- CINEMA_PUBLIC_ORIGIN=https://pappare.ru.
- CINEMA_HOLD_MINUTES=10.

Для киноуведомлений нужны TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID. Киноуведомления пока идут напрямую в Telegram: ранее настроенный relay обычных броней их не обслуживает. Проверьте сетевую доступность Telegram с VPS. Не включайте оплату до проверки уведомлений.

Файл настроек должен быть доступен только пользователю приложения (chmod 600 .env.local). Если PM2/systemd/Docker уже задаёт переменные, обновлять нужно и этот источник: значения окружения имеют приоритет над файлом.

При первой работе API автоматически создаёт cinema_* таблицы. Данные вечеров, фото, мест, заказов и журнал ручной оплаты хранятся в PostgreSQL. Базу нельзя удалять при релизе.

## Команды в действующей папке проекта

~~~bash
git status --short
git pull --ff-only origin main
npm ci && npm run test:cinema && npm run build
~~~

Сборку выполнять с установленными devDependencies (не npm ci --omit=dev). Удалить только переменную CINEMA_BUILD_DIR из окружения сборки, если она была задана: на VPS используется обычная .next.

После успешной сборки перезапустить существующий процесс: для PM2 — pm2 restart ИМЯ_ПРОЦЕССА --update-env; для systemd — sudo systemctl restart ИМЯ_СЛУЖБЫ. Имена сначала проверить. Для Docker нужно собрать новый образ по имеющейся конфигурации. Не запускать второй экземпляр на занятом порту.

## Проверка

Открыть https://pappare.ru/kino и https://pappare.ru/kino/admin. В кабинете использовать новый серверный ключ. Проверить афишу 11 октября, 18:00, 2500 ₽, 20 мест.

С согласия владельца создать явно тестовую телефонную бронь, увидеть её на публичной схеме в отдельном окне (обновление до 5 секунд), проверить сообщение Telegram и отменить тестовую бронь в кабинете. Не отмечать её оплаченной: отмена оплаченного заказа требует отдельной процедуры возврата.

Проверить редактирование афиши и загрузку фото, сохранность после перезапуска. Резервные копии PostgreSQL теперь содержат и фотографии.

Защищённый POST /api/cinema/notifications/retry с Authorization: Bearer CINEMA_ADMIN_SECRET повторяет недоставленные сообщения. Настроить вызов раз в минуту через существующий планировщик, не помещая секрет в публичные файлы или логи.

## Ограничения этого релиза

ЮKassa, фискальные чеки и автоматические возвраты ещё не подключены. При ручном подтверждении оплаты администратор обязан сверить деньги и указать подтверждение. Запись этого действия сохраняется в БД. Подготовленные условия и политика не заменяют проверку юридических и операционных настроек бизнеса.

Обновление кода на GitHub само по себе не подтверждает обновление VPS. Если к main подключён автодеплой Vercel, он может запуститься отдельно.

## Если npm ci сообщает Missing ... from lock file

Не продолжать сборку после ошибки установки. Сначала проверить фактический коммит и рабочие файлы:

~~~bash
cd /var/www/pappare
node -v
npm -v
git rev-parse --short HEAD
git status --short
git diff --quiet HEAD -- package.json package-lock.json; printf 'dependency-files-differ=%s\n' "$?"
~~~

Код 0 у последней проверки означает, что файлы совпадают с текущим коммитом, 1 — есть локальные изменения. Нельзя автоматически удалять серверные изменения или lock-файл. Если git pull не прошёл, сначала выяснить причину по его выводу.

Файл package-lock.json коммита b7f183e проверен в отдельной пустой папке командами npm ci --dry-run --ignore-scripts в npm 9 и 10; обе завершились успешно. В нём есть @esbuild/linux-x64 0.28.2 и остальные платформенные зависимости esbuild. Для точной диагностики серверной ошибки нужен вывод команд выше и первые строки сообщения npm.
